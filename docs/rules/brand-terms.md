# 品牌用語清單

清單資料檔是 `data/rules/brand-terms.json`，來源是研究筆記 `docs/research/candidates-2026.md` 第 4 節。上線關卡「品牌用語掃描」與核對第二層的檢核表都讀這個檔案。

## 兩級

| 級別 | 欄位 | 範圍 | 例 |
|---|---|---|---|
| 品牌用語 | `brand` | 整理者撰寫的全部文字禁用，包括網站文案、摘要、議題區名稱、元素名稱、網址與檔名 | 臺中味、Taichung Way、六星、168、換欣 |
| 陣營高頻詞 | `frequent` | 網站文案、議題區、元素清單等禁用；摘要中有中性替代詞時應替換，關卡不擋，由核對第二層判斷 | 幸福、旗艦、升級、安心、臺中隊 |

原文引述、出處快照、出處的原網址、存檔網址與標題是候選人本人的文字，不在掃描範圍內。

## 例外：引用 repo 文件

整理方法頁照原文公開本站實際使用的規則文件與清單（品牌用語清單、分類規則、檢核表、提示詞、抽取指示等），不改寫、不遮字，讀者看到的就是抽取、核對與關卡實際讀取的檔案。這些文件會寫出品牌用語作為例子，所以比照原文引述，品牌用語掃描不掃。

- 收錄哪些文件只定義在 `site/js/repo-documents.js` 的 `REPO_DOCUMENTS`。建置指令把它們逐字複製到網站目錄的 `data/repo-files/<repo 路徑>`，頁面在標了 `data-repo-file="<repo 路徑>"` 的「引用 repo 文件」容器裡呈現。
- 品牌用語掃描只跳過與 repo 檔案逐字相同的副本。內容不一致的檔案照常掃描。
- 上線關卡「引用 repo 文件與 repo 檔案逐字相同」（`repo-documents`）另外檢查：`data/repo-files/` 底下每個檔案都在清單中、與 repo 檔案逐字相同；必要文件都在；頁面上的 `data-repo-file` 只標註清單中的文件。任一項不符就不通過，這個例外因此無法用來夾帶整理者自己寫的文案。
- 頁面上整理者自己寫的說明文字，包括容器的標題與標籤，照常受掃描。

## 收錄原則

- 收候選人競選識別使用的名稱、口號、數字代號、政策專名，以及英文寫法與已證實的諧音（例如「啟程」「換欣」）。
- 研究筆記標為「推測」、沒有來源的諧音不收。
- 未驗證是否本屆使用、或只見於網友延伸與媒體標題的用語，保守收錄並在 `note` 註明。
- 描述性的機關或設施名稱（例如「長照處」「臺中農易通 APP」）不收，摘要需要時可以直接寫出。帶諧音或造詞的政策名稱（例如「好孕專車」）照收。
- 會擋到一般行文的詞，收較長的全名（例如收「山和谷音樂祭」而不收「山和谷」，以免擋到「梨山和谷關」），或改列陣營高頻詞（例如「臺中集合」）。
- 詞中不含候選人姓名與政黨名稱。研究筆記的「台中的市長何欣純」只收不含姓名的部分會誤擋一般文字，所以不收。
- `candidate` 是候選人識別碼；兩陣營都用的詞記在先使用的一方，`note` 註明另一方。

## 比對方式

比對前文字與詞都先正規化：全形轉半形、英文轉小寫、「臺」視為「台」、去掉空白與標點符號（小數點保留）。所以「台中味」「TAICHUNG  way」「taichungway.tw」都會命中。

- 純數字的詞（168、12345、4321）單獨比對：標點換成空白而不是去掉，前後不得緊接數字或小數。「1,680 元」「0.168」「168.5」「第 12、345 號」都不算命中。
- 結尾是英文字母的詞，後面不得緊接字母，「Taichung We」不擋「Taichung Weather」。
- CSS 與 JS 檔整份掃品牌用語；陣營高頻詞只掃字串內容，註解與程式識別字不算網站文案。

## 改版

改動清單內容就把 `version` 加一。核對第二層記錄檢核表版本，品牌用語清單改版後，已通過的政見依核對流程重新判定。
