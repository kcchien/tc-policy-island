原文公開的文件

本頁標示「公開原文」的區塊，是本站整理與核對政見時實際使用的規則、清單與指示，照原文公開，不改寫、不遮字。讀者看到的，就是整理與核對時實際讀取的內容。每個區塊都附「在 GitHub 查看」連結，可以對照原始檔案與修改紀錄。

規則文件依原文的標題、清單與表格排版；檢核表與品牌用語清單排成清單與表格，內容照原文，不增刪、不換字。AI 核對指示照原文逐行呈現。這些文件是寫給整理流程與 AI 讀的，會出現檔案位置、指令與欄位名稱等技術細節，照原文保留。

這些文件為了說明規則，會寫出候選人的品牌用語作為例子。本站文字的品牌用語檢查因此比照原文引述，不檢查這些區塊。為了不讓這個例外被拿來夾帶整理者自己寫的文字，每次上線前都會自動比對每個區塊與原始檔案逐字相同，不一致就不上線。本頁其他說明文字照常檢查。

只收一手來源

本站只收候選人本人或中選會發布的一手來源：候選人官網、官方臉書、政見發表會、選舉公報，官網優先。媒體報導等二手來源不收。

理由：媒體報導經過記者與媒體的選擇與改寫，各家媒體對每位候選人的報導量也不同。只收一手來源，三位候選人適用同一個標準，讀者也能回到原始頁面查證。

本站依目前取得的一手來源整理，可能有缺漏，並未涵蓋候選人的所有公開發言，也不表示已全面搜尋所有網站。來源尚未取得、資料尚未整理或尚未通過核對，都可能使公開資料不完整；個別空欄的原因不能只靠空欄判定。

收錄狀態、來源狀態與篩選結果

  • 收錄狀態：本站截至資料截止日，是否收錄這位候選人在這個議題通過核對的政見。尚未收錄不代表候選人未提出。
  • 來源狀態：本站目前取得的政見一手來源情況，不代表候選人所有公開發言的全貌。候選人基本資料的出處不當成政見來源。
  • 篩選結果：本站已收錄資料中，符合你目前篩選條件的政見。沒有符合結果不改變原本的收錄狀態，也不代表候選人未提出。

候選人資料

索引的「候選人」分頁與表格檢視欄頭的「看候選人資料」開啟候選人資料卡。卡片只放中選會公開的五個欄位：姓名、政黨、出生年、學歷、經歷。三位候選人欄位相同，卡片同尺寸、同字級，依候選人排序規則排列。

  • 來源只用中選會：學歷與經歷取自中選會選舉公報，出生年取自同一份公報，並與中選會選舉資料庫比對。2026 年選舉公報公布前，用三位候選人最近一次都有公報的 2024 年第11屆立法委員選舉（區域）臺中市各選舉區公報。每張卡片註明選舉年份與選舉別。
  • 逐字呈現：學歷與經歷照公報原文，公報上一個項目符號列成一項；公報上沒有分項的整段文字照原樣呈現，不自行斷句。不改寫、不摘要，也不加整理者撰寫的介紹或評語。
  • 不收政績、爭議、財產、媒體報導與候選人自我介紹。
  • 每張卡片附出處連結、原文存檔（本站存下的公報文字）、網頁備份與擷取日期。公報有部分文字因字型無法直接轉成文字、需要比對公報影像還原的，卡片上的「原文存檔說明」會註明，還原方法見下方的候選人資料整理方法。
  • 核對：學歷與經歷須逐字出現在原文存檔中（原文逐字比對），通過才公開。候選人資料沒有摘要，所以不做 AI 檢查。每次上線前另外自動檢查三人欄位相同、出處是中選會網站上的選舉公報。
  • 學歷與經歷是候選人本人的文字，比照原文引述，不受品牌用語掃描。

整理與核對

  1. 整理：AI 依「政見整理指示」讀取一手來源，整理出政見、原文引述與摘要，並存下原文存檔（出處頁面當下的文字）與網頁備份（送交第三方網頁存檔服務保存的副本）。三位候選人共用同一份整理指示。
  2. 第一道核對：原文逐字比對。由程式比對：原文引述在統一全形半形、去掉空白與換行、統一標點之後，必須逐字出現在原文存檔中。字詞不同就不通過。
  3. 第二道核對：AI 依公開檢核表檢查。每條政見另開一次全新的 AI 對話，看不到整理過程，只拿到檢核表、品牌用語清單、摘要與原文引述，候選人姓名與政黨以「○○」遮蔽。AI 依檢核表判定通過或退回，並寫下理由。三位候選人共用同一份檢核表與核對指示。
  4. 公開：兩道核對都通過的政見才會公開，其餘由程式排除。每條政見在政見卡片上附核對紀錄：結果與日期。

原文逐字比對確認引用文字與原文一致，AI 依公開檢核表檢查摘要是否忠於原文、有無評價或品牌用語。這不是政見內容的事實查核，也不是可行性評估或履約保證。AI 仍可能出錯，本站未經人工逐筆審查，請回到出處自行查證。

檢核表與核對指示改了內容就換新版本。已通過的政見遇到新版檢核表，要依新版重新核對。

核對報告

核對報告記錄各候選人在第二道核對的通過率、退回次數與刪除筆數，對全部政見執行核對後產生，公開在下方。

給讀者的工具

這些工具都以議題區為單位、三位候選人並排，不評分、不推薦。讀者在這台裝置上做的選擇只留在自己的瀏覽器，本站不收集、不統計、也不顯示其他人的選擇。

  • 下一題與閱讀進度：卡片上的「下一題」依議題區編號走完二十題；看過的議題區在索引與表格上打一個淡勾，只記在這台裝置，可以隨時清除，沒有獎勵也沒有完成訊息。
  • 我的對照單：勾選在意的政見後，頁首的對照單只列出這些政見所在的議題區，三欄仍並排、本站尚未收錄的欄位照常顯示收錄狀態，列印也一樣，可以用網址帶走。勾選只決定看哪些議題區，不決定看哪位候選人。
  • 只看出處說法不一的政見：候選人自己的兩個一手來源說法不同時，兩說照原文並列，不替候選人選一個；篩選只把這些政見挑出來。
  • 收錄說明：三位候選人都有相同的展開入口，可查看來源狀態、本站收錄筆數、原始政見條目與資料截止日。整理時的拆分方式與目前取得的來源範圍會影響筆數，數量不代表政見品質或收錄完整度；尚未統計的條目數不當成零。
  • 政見序號：每位候選人在目前議題區的閱讀位置，沿用原有順序，篩選後不重編。序號不是排名，不加入複製或朗讀的文字。
  • 場景設定：時段、暫停、名牌、全景與背景音樂放在可展開區域，收合不改變原本狀態。議題查找、隨機一題與檢視切換仍可直接使用。卡片內的篩選只作用於目前議題，全站條件留在背景，關閉卡片後仍保留。
  • 複製與朗讀：每條政見可以複製成一段帶出處連結的文字，或播放朗讀音檔（見下一節）。三位候選人同一格式、同一聲音。
  • 一手來源回報：本站尚未收錄的欄位旁，可以把你找到的候選人公開說法連結給我們。只收候選人本人或中選會發布的來源，補上的政見一樣要通過兩層核對才會公開。
  • 選舉時程：頁首列出的日期與距投票日天數只取中選會或臺中市選舉委員會的公告，與候選人無關。
  • 島嶼檢視點開議題區時，三位候選人人物同時從候選人廣場出發、同時抵達，各自站到該格自己的標記旁；本站尚未收錄政見的候選人也一樣走到灰色標記旁。

政見朗讀

政見的朗讀音檔由語音合成服務依固定設定預先生成，三位候選人同一個聲音與語速；設定與每條音檔的對照清單照原文公開在下方。

  • 朗讀的內容只有政見摘要與原文引述，三位候選人用同一套念法：先念「摘要」，停一秒再逐則念「原文引述」，不加其他文字。
  • 全有或全無：三位候選人公開的每一條政見都有音檔，網站才放上音檔；缺任何一條，整站都不放。每次上線前自動檢查。
  • 原文以畫面上的文字為準，音檔只是方便收聽。

中立規則

只要有一處看起來偏向某位候選人，整站就不可信。以下規則是硬性限制，任何設計或內容調整都不能違反。這份清單是下方決策紀錄的白話摘要，兩者有出入時以決策紀錄原文為準。

  • 候選人排列：抽籤後依號次，抽籤前依姓名筆畫。
  • 三位候選人的欄位寬度、字級與標記大小都相同。本站不評分、不排名、不推薦。
  • 島上每個議題區，每位候選人只有一個同尺寸的標記，只表示本站是否收錄政見，不表示政見多寡。尚未收錄不代表候選人未提出；篩選時標記亮起表示有符合的政見。
  • 配色不用任何政黨色（藍、綠、白、橘），也不用候選人的識別色（海洋藍、粉紅、桃紅、紫）。三位候選人用同一個中性色，以形狀區分。
  • 島上的在地感元素只取與市政建設無關的自然景觀、小吃、老建築，不放與任何市長任期有關的地標。
  • 只收一手來源，不收媒體報導。
  • 網站名稱、文案與網址不用任何候選人的品牌用語或其諧音。
  • 不放民調、捐款或催票連結，也不放任何陣營的標誌或照片。
  • 每條政見附出處連結與原文存檔，通過兩道核對才公開。
  • 分類規則、檢核表、AI 核對指示、政見整理指示與完整流程都公開在本頁。
  • 本站只統計頁面瀏覽與出處點擊的次數，不記錄讀者是誰。統計只給維護者判斷改動有沒有用，不依點擊量調整排序或內容，也不公開依候選人分的點擊數。
  • 上線不靠人工放行，改由每次上線前的自動檢查把關：不含品牌用語、不用禁用色、公開資料全數通過核對、三位候選人版面一致、島上人物與動態不隨政見改變、公開原文與原始檔案逐字相同、畫面文字不外漏技術細節。任一項沒過就不上線。

更正管道

發現錯誤請到 GitHub Issues 回報，附上政見卡片上的政見連結，以及你認為有誤的地方。處理過程公開在 Issues 上。修正後的政見一樣要重新通過兩層核對才會公開。

如果本站尚未收錄某位候選人在這個議題的政見，而你找到這位候選人在這題的公開說法，可以按空欄位下方的「把連結給我們」，或直接到 GitHub 填一手來源回報。這裡只收候選人本人或中選會發布的來源（候選人官網、官方臉書、政見發表會、選舉公報），不收媒體報導，也不收對候選人的意見或評價。補上的政見一樣要通過兩層核對才會公開。

本站由 AI 依公開資料自動整理，與任何候選人或政黨無關，未經人工逐筆審查。
