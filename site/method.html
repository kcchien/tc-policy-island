揭露聲明

  • 本站與任何候選人或政黨無關。
  • 整理者不具名。內容可不可信，不靠整理者的身分，而靠本頁公開的流程，以及每條政見附的原文引述、出處與出處快照，任何人都能自行查證。

引用 repo 文件

本頁標示「引用 repo 文件」的區塊，是本站 repo 內實際使用的文件原文，建置網站時逐字複製，不改寫、不遮字。讀者看到的就是抽取、核對與上線關卡實際讀取的內容。每個區塊都附原檔連結，可以直接對照。

Markdown 文件依原檔的標題、清單與表格排版；檢核表與品牌用語清單是 JSON 檔，排成清單與表格呈現，欄位值照原檔，不增刪、不換字。核對第二層提示詞照原檔逐行呈現。

這些文件為了說明規則，會寫出候選人的品牌用語作為例子。品牌用語掃描因此比照原文引述，不掃這些區塊。為了不讓這個例外被拿來夾帶整理者自己寫的文字，上線關卡會逐字比對每個區塊與它標註的 repo 檔案，不一致就不部署。本頁其他說明文字照常受品牌用語掃描。

只收一手來源

本站只收候選人本人或中選會發布的一手來源：候選人官網、官方臉書、政見發表會、選舉公報，官網優先。媒體報導等二手來源不收。

理由：媒體報導經過記者與媒體的選擇與改寫，各家媒體對每位候選人的報導量也不同。只收一手來源，三位候選人適用同一個標準，讀者也能回到原始頁面查證。

議題區與分類規則

議題區依台中市政府的局處職掌劃分，不照任何一位候選人的政見架構。一條政見只歸入一個議題區。議題區的拆法會影響每位候選人看起來有幾條政見，所以分類規則全文公開。

抽取與核對

  1. 抽取：AI 依「政見抽取指示」讀取一手來源，整理出政見、原文引述與摘要，並存下出處快照與存檔網址。三位候選人共用同一份抽取指示。
  2. 核對第一層：程式比對。原文引述在統一全形半形、去掉空白與換行、統一標點之後，必須逐字出現在出處快照中。字詞不同就不通過。
  3. 核對第二層：每條政見另開一個全新的 AI session，看不到抽取過程，只拿到檢核表、品牌用語清單、摘要與原文引述，候選人姓名與政黨以「○○」遮蔽。它依檢核表判定通過或退回，並寫下理由。三位候選人共用同一份檢核表與提示詞。
  4. 公開：兩層都通過的政見才會進入公開資料集，其餘在建置時由程式排除。每條政見在政見卡片上附核對紀錄：結果、檢核表版本與日期。

檢核表與提示詞改內容就升版。已通過的政見遇到新版檢核表，要依新版重新核對。

核對報告

核對報告記錄各候選人第二層的通過率、退回次數與刪除筆數，對全部政見執行核對後產生，放在 repo 的 data/verification/report.md。

中立規則

只要有一處看起來偏向某位候選人，整站就不可信。以下規則是硬性限制，任何設計或內容調整都不能違反。這份清單是下方決策紀錄的白話摘要，兩者有出入時以決策紀錄原文為準。

  • 候選人排列：抽籤後依號次，抽籤前依姓名筆畫。
  • 三位候選人的欄位寬度、字級與標記大小都相同。本站不評分、不排名、不推薦。
  • 島上每個議題區，每位候選人只有一個同尺寸的標記，只表示有沒有政見，不表示政見多寡。
  • 配色不用任何政黨色（藍、綠、白、橘），也不用候選人的識別色（海洋藍、粉紅、桃紅、紫）。三位候選人用同一個中性色，以形狀區分。
  • 島上的在地感元素只取與市政建設無關的自然景觀、小吃、老建築，不放與任何市長任期有關的地標。
  • 只收一手來源，不收媒體報導。
  • 網站名稱、文案與網址不用任何候選人的品牌用語或其諧音。
  • 不放民調、捐款或催票連結，也不放任何陣營的標誌或照片。
  • 每條政見附出處連結與出處快照，通過兩層核對才公開。
  • 分類規則、檢核表、提示詞、抽取指示與完整流程都公開在本頁。
  • 上線不靠人工放行，改由自動化上線關卡把關：品牌用語掃描、禁用色檢查、公開資料全數通過核對、三位候選人版面一致、引用 repo 文件與原檔逐字相同。任一項沒過就不部署。

更正管道

發現錯誤請到 GitHub Issues 回報，附上政見卡片上的政見連結，以及你認為有誤的地方。處理過程公開在 Issues 上。修正後的政見一樣要重新通過兩層核對才會公開。
